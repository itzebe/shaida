# Safety, Privacy and Limitations Statement

*Follows the official `docs/05_templates/SAFETY_AND_LIMITATIONS.md` structure.*

## 1. Compliance with hackathon rules

- [x] **No live/institutional system accessed or tested.** No request is made to INEC, IReV, BVAS,
      or any institutional infrastructure at any point. The system runs entirely offline against
      synthetic data. There is no code path that contacts an external electoral host.
- [x] **Only synthetic, public or authorised data.** The official synthetic pack plus synthetic
      data generated by this project. No scraping, no personal data, no real voter records.
- [x] **Nonpartisan; no persuasion or microtargeting.** No candidate or party entity exists in the
      schema, and the tool has no channel through which to reach a voter.
- [x] **Human oversight for consequential decisions.** There is no automated decision path. The
      only way a report is resolved is a human recording a decision **and a mandatory reason**,
      written to the tamper-evident audit log.

## 2. Risk register

| Risk | Who could be harmed | Likelihood | Impact | Mitigation | Residual |
|---|---|---|---|---|---|
| **False positive** (a benign record is flagged) | a polling unit's officials, if a reviewer over-reads a flag | Medium | Low–Medium | Two-tier design; advisory findings labelled advisory; **every finding ships with plausible innocent explanations to rule out first**; no automatic publication | **Medium** — `R3` produces false positives on this pack and is documented |
| **False negative** (a real anomaly is missed) | the public's ability to spot a problem | Medium | Medium | High recall (97.6 %); multiple independent rules; a rejected broad heuristic was measured, not adopted | **Low–Medium** — one labelled case missed by `R3` |
| **Bias against a language or group** | non-English reporters; assistive model users | Medium | Medium | Assistive components **abstain** and never create findings, so bias cannot become an accusation; interface translated into 5 languages | **Medium** — the assistive model is untested on non-English input; stated openly |
| **Privacy breach / re-identification** | sensitive reporters (intimidation, violence) | Low | **High** | Identity-free schema (no field exists); location off by default and coarsened to ~1 km; k-anonymity suppression, never rounding; sensitive categories handled more strictly | **Low**, but no DPIA has been performed |
| **Misuse by bad actors** (flooding with false reports) | reviewers; the credibility of genuine reports | Medium | Medium | Per-client rate limiting; duplicate clustering; nothing is published automatically | **Medium** — a determined flooder can still consume reviewer time |
| **Adversarial manipulation** (crafted input to game a rule) | the reviewer | Low | Medium | Rules are deterministic and stated; adversarial inputs are covered in the test suite; no model on the decision path to poison | **Low** |
| **Over-reliance by users** (a flag treated as a conclusion) | the public, if a flag is reported as fact | Medium | **High** | UI states on every page that SHAIDA flags and does not judge; verdict vocabulary is blocked at runtime; every flag carries a required human decision with a reason | **Low–Medium** |
| **Unverified accusation reaching the public** | any named or implied person | Low | **High** | The tool publishes nothing automatically; aggregation has a k-anonymity floor; API tested to contain no verdict language | **Low** |

## 3. Privacy and data protection

**Personal data collected: none by default.**

| Data | Collected | Basis / safeguard |
|---|---|---|
| Reporter name, phone, email, account | **No** | no such field exists in the schema |
| IP address | **No** | not stored |
| Reporter *role* | Yes | a role (citizen/observer/party agent/official), not a person |
| Narrative text | Yes | the substance of the report; length-bounded and validated |
| Evidence file | Hashed | SHA-256 computed on the device; the hash is what is trusted |
| Precise location | Off by default | if used, coarsened to ~1 km; never returned exactly |
| Aggregates | Yes | k-anonymity floor (default 5); cells below it are suppressed entirely, never rounded |

- **Lawful basis / consent:** none is claimed, because no personal data is collected. This is a
  deliberate design choice, not an oversight.
- **Minimisation:** enforced by the schema, not by policy — `test_no_reporter_identity_is_stored`.
- **Retention and deletion:** the store is a prototype SQLite file. **No production retention or
  deletion policy is claimed**, because claiming one without a live deployment would be dishonest.
  A retention policy is a precondition for real use.
- **Access controls:** none beyond the host filesystem; the prototype has no accounts by design,
  since accounts imply identity.
- **Anonymisation method:** identity is never collected (so there is nothing to anonymise);
  location is coarsened; aggregates are suppressed below the floor.

NDPA 2023 alignment is described in [`DATA-PROTECTION.md`](DATA-PROTECTION.md). A formal DPIA has
**not** been performed and is listed as a precondition for real use.

## 4. Known limitations

**What the system cannot do:**

- It cannot tell you whether an election result is correct, whether fraud occurred, or who won. It
  has no such capability and is designed to have none.
- It cannot verify that an incident narrative is true. It records what someone reported, with
  provenance.
- It cannot establish that a photo depicts what it claims. It proves only that *this* file was
  submitted at *this* time and was not altered since — the same guarantee C2PA offers, and no
  more. **It does not detect deepfakes or manipulation.**
- It cannot match claims in languages outside its archive, and its assistive model is untested on
  non-English text.
- It cannot operate at national scale as built; the store is single-instance SQLite.

**Conditions where it fails:**

- `R3_digit_transposition` misses the pack's single transposition case, because that case is a
  single-digit substitution rather than an adjacent swap (documented in
  [`../evaluation/RESULTS.md`](../evaluation/RESULTS.md) §2.2).
- Clustering performs unusually well on the synthetic pack because it is repetitive; real incident
  narratives vary far more.
- The severity assist is weak (0.40 exact accuracy against a 0.25 baseline) because a reporter's
  own framing of seriousness is a genuinely weak signal.

**Performance gaps by language/region:** the assistive model is evaluated on English only. Regional
and linguistic fairness is **unmeasured**, and this is stated rather than assumed away.

## 5. Conditions for further testing

Before this prototype is tested with any real user or real data, the following are required:

1. **Independent security review** of the API and the hash chain.
2. **A DPIA under the NDPA 2023**, with a defined lawful basis, retention and deletion policy.
3. **Native-speaker review** of every non-English string (currently first-pass translations).
4. **An accessibility audit with assistive-technology users**, beyond the automated axe-core pass.
5. **An ethics review**, and a written agreement with any CSO that would operate it.
6. **A controlled sandbox pilot** with no connection to any production electoral system.
7. **Legal review** against electoral law and defamation risk.
8. **Load and adversarial testing** at a scale this prototype has not been tested at.

## 6. Statement

> **This prototype is not approved for operational electoral deployment.**

It does not access any live electoral system, it declares no results, and it makes no accusation.
Winning a competition would not change that. Every output is a flag for a human to resolve, and the
conditions in §5 must be met before any real use.
