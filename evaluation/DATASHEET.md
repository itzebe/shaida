# Datasheet: SHAIDA datasets

*Follows the official `docs/05_templates/DATASHEET.md` structure.*

---

## Dataset 1 — Official synthetic starter pack (used, not created by us)

1. **Motivation.** Provided by Rise Networks and partners as the shared, safe corpus for the
   #AI4Elections Hackathon so that teams work on realistic-shaped electoral data **without touching
   real voter data or live systems**. Not funded by us; created by the organisers.

2. **Composition.** Eight files, 4 220 rows in total. All data is fictional: party labels A–E,
   polling-unit IDs `SIM-#####`, incidents, claims and survey respondents do not refer to real
   parties, units, people or events. States and zones are real geography used only for realism;
   LGAs and wards are invented labels.

   | File | Rows | What each record is |
   |---|---|---|
   | `polling_units_synthetic.csv` | 900 | unit attributes (zone, state, LGA, ward, settlement, registered voters, accessibility, grid power, network coverage, distance) |
   | `results_synthetic.csv` | 900 | pu_id, registered, accredited, votes_A..E, rejected; **~5 % carry injected inconsistencies** |
   | `anomaly_labels_HELD_OUT.csv` | 900 | the answer key for the injected anomalies |
   | `misinformation_claims_synthetic.jsonl` | 300 | claim_id, text, label, language, channel, synthetic-media flag, spread score |
   | `incident_reports_synthetic.csv` | 400 | incident_id, timestamp, location ids, category, description, severity 0–4, reporter type, verified flag, photo-evidence flag |
   | `logistics_deliveries_synthetic.csv` | 300 | delivery logistics per unit |
   | `accessibility_barriers_survey_synthetic.csv` | 500 | simulated respondents: state, settlement, age band, gender, disability type, preferred language, main barrier, confidence |
   | `voter_info_faq_multilingual.csv` | 20 | FAQ questions in English + draft Pidgin; ha/yo/ig deliberately left empty |

   **Label definitions** for the anomaly types: `accredited_exceeds_registered`, `sum_mismatch`,
   `digit_transposition`, `suspicious_round_numbers`, `duplicated_from_previous_unit`.
   **Class balance:** 42 of 900 result records are labelled anomalous (~4.7 %), a deliberately
   imbalanced, realistic shape. **Missing data:** the multilingual FAQ file leaves ha/yo/ig empty by
   design, to invite community translation. **Personal or sensitive data:** none — all records are
   fictional. **Synthetic:** 100 %.

3. **Collection process.** Generated by the organisers. No sampling of real people, no consent
   required because no real person is represented, no personal data scraped. Licence: CC BY 4.0 per
   the hackathon repository terms.

4. **Preprocessing.** Loaded read-only. No cleaning or transformation is applied to the source
   files; the application computes derived values (findings, hashes) into its own store and never
   writes back to the pack. Our aggregation adds a **k-anonymity suppression floor** (default 5):
   cells below the floor are suppressed entirely, never rounded.

5. **Uses.**
   - *Intended:* evaluating the deterministic rule engine against the held-out labels; training and
     testing the severity assist; evaluating the claim matcher; demonstrating the full workflow.
   - *Must not be used for:* any inference about real elections, real parties, real geography or
     real behaviour. The pack's own data dictionary says this and we repeat it.

6. **Distribution.** Committed to the repository under `data/official-synthetic/`. CC BY 4.0.
   Versioned with the repository. The pack is small (336 KB) and its integrity is protected by git.

7. **Maintenance.** Owned by the organisers. Errors should be reported to them. We retain and
   redistribute the pack unchanged under its licence.

8. **Known limitations and biases.** Distributions are deliberately simplistic. Geography is real
   but all finer labels are invented. The incident narratives are machine-generated and unusually
   repetitive, which is why our clustering result (95.8 % queue reduction) is an **upper bound** and
   not a field estimate. Language coverage is English plus some Pidgin; there is no Hausa, Yoruba or
   Igbo incident text, so **linguistic fairness of the assistive model is unmeasured**.

## Dataset 2 — SHAIDA demonstration reports (created by us)

1. **Motivation.** So that a reviewer or judge has something meaningful to inspect without typing
   reports by hand, and so the UI can be demonstrated end to end.

2. **Composition.** 12 invented incident reports covering the main categories, plus 1 recorded
   review action. Fields: category, narrative, state, LGA, polling-unit code, reporter role,
   optional severity, optional coarse coordinates. **No personal or sensitive data** — no real
   person is represented, and no identity field exists. **Synthetic: 100 %.**

3. **Collection process.** Written by hand for this project. No collection from any source. No
   consent needed (no real person). Licence: CC BY 4.0.

4. **Preprocessing.** None. Every record is submitted through the same public API a real report
   would use, so the demonstration exercises the real path rather than seeding the database
   directly.

5. **Uses.**
   - *Intended:* UI demonstration, screenshot capture, end-to-end verification.
   - *Must not be used for:* evaluation of accuracy (it is too small and deliberately varied), or
     any claim about real incidents.

6. **Distribution.** Generated on demand by `scripts/seed_demo.py`; **not committed as data**, so
   there is no stale copy. The generator is committed instead.

7. **Maintenance.** Owned by this project. Regenerate with
   `python scripts/seed_demo.py http://127.0.0.1:8000`.

8. **Known limitations and biases.** Twelve records cannot represent the diversity of real
   incidents. The polling-unit codes use a `DEMO-` prefix specifically so they can never be confused
   with the organisers' `SIM-` codes or with any real unit identifier.

## Dataset 3 — Derived evaluation outputs (created by us)

1. **Motivation.** To make every reported metric reproducible and machine-checkable.

2. **Composition.** `evaluation/results.json` — precision, recall, F1 (overall, by tier, per rule),
   flag rate, clean false-alarm rate, structural substantiation, severity-assist held-out scores,
   claim-matcher scores, clustering reduction, triage lift, and the measured rejected heuristic. No
   personal data. **Synthetic: 100 %** (derived entirely from Datasets 1 and 2).

3. **Collection process.** Produced by `evaluation/evaluate.py`. Deterministic, single-threaded,
   no randomness.

4. **Preprocessing.** Deterministic rule application; deterministic 75/25 split for the severity
   assist; a deterministic `index % 4 == 0` sample for the claim matcher.

5. **Uses.** Reporting results; locking them into regression tests
   (`backend/tests/test_evaluation_guards.py`). *Must not be used* as evidence about real elections.

6. **Distribution.** Committed, regenerated by the documented command.

7. **Maintenance.** Owned by this project. Regenerate with `python evaluation/evaluate.py`.

8. **Known limitations and biases.** Every number inherits the synthetic nature of Dataset 1. Small
   test sets (100 and 75 items) mean no confidence intervals are claimed.

---

## Cross-cutting statement

**No dataset in this project contains personal data, real electoral data, or scraped content.** No
live electoral system has been accessed, and no real voter or observer is represented anywhere.
Aggregates produced by the application are suppressed below a k-anonymity floor of 5 rather than
rounded, so an individual report cannot be recovered by subtraction.
